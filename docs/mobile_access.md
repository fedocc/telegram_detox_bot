# Доступ с iPhone без VPN

Адрес: **https://detox.45-80-228-215.sslip.io/**.
Mac для управления: **http://127.0.0.1:8787/devices** (через существующее локальное SSH-подключение).

## Подключение

1. На Mac открыть «Доверенные устройства» → «Добавить телефон».
2. На iPhone открыть внешний адрес в Safari. Для отдельного значка сначала выбрать
   «Поделиться» → «На экран Домой», затем открыть сайт через этот значок.
3. Ввести 12 цифр приглашения с Mac и создать ключ доступа через Face ID или код
   разблокировки. Приглашение действует пять минут и используется один раз.
   Вместо ввода можно отсканировать QR-код и подключить обычную вкладку Safari.
4. Сверить **отдельный шестизначный код** на iPhone и в запросе на Mac. Только после
   совпадения нажать на Mac «Код совпадает — подтвердить» (в течение 15 минут).
5. На iPhone нажать «Войти с ключом доступа».

Подключать нужно тот браузер, в котором собираетесь пользоваться сайтом: Safari
и значок на главном экране могут иметь разные хранилища. Если подключили Safari,
а значок просит приглашение, подключите значок отдельно. После очистки данных
сайта тоже понадобится новое приглашение. Приватный режим для постоянного входа
не подходит.

## Что защищено

- Публичный адрес показывает только экран входа. Сообщения, контакты, аватарки,
  вложения, уведомления и действия требуют подтверждённого устройства и сессии.
- Ключ доступа проверяется стандартной библиотекой WebAuthn. Проверяются точный
  сайт, RP ID, подпись, разблокировка аутентификатора и одноразовый запрос.
  Регистрация ключа сама по себе не открывает переписку: нужна сверка на Mac.
- Подтверждается **браузер с ключом**, а не определённая модель телефона. Помимо
  passkey требуется независимая защищённая cookie браузера. Один синхронизированный
  через iCloud ключ не подключает другой браузер автоматически. Аппаратная
  аттестация конкретного iPhone не используется.
- Сессия действует 12 часов без продления при активности; затем нужен новый вход
  с ключом. Доверие к браузеру действует 180 дней. На телефоне есть кнопка «Выйти».
- Отзыв на Mac закрывает последующие запросы, прерывает обслуживаемые приложением
  потоки медиа и отключает связанные push-подписки. Уже скачанные данные и уже
  доставленные уведомления удалить с чужого устройства невозможно.
- Панель управления устройствами доступна только через локальное подключение Mac.
  На внешнем слушателе она закрыта независимо от заголовков запроса; Caddy
  дополнительно возвращает 404 для её адресов.
- Ограничены попытки входа, размер и время чтения запросов. Журнал хранит до 1000
  событий за 30 дней: тип события, название устройства, IP и время, без переписки,
  ключей, кодов приглашения и содержимого запросов.
- Cookie имеют Secure, HttpOnly, SameSite=Strict и префикс `__Host-`; сервер хранит
  хеши секретов привязки, приглашений и сессий. Для действий применяется отдельный
  CSRF-токен сессии, проверяются Origin и Sec-Fetch-Site, запрещено встраивание
  страницы в чужой сайт.

Все устройства используют прежние серверные таймеры и квоты. Подключение телефона
не создаёт дополнительных открытий Telegram и не сбрасывает ограничения.

Старые push-подписки без привязки к устройству отключаются при включении защиты;
при необходимости уведомления включаются заново в подтверждённом приложении.
Локальные режимы уведомлений Mac ON / PAUSE / OFF продолжают работать отдельно.

## Сервер

- Зависимости: `webauthn==3.0.1`, `qrcode==8.2`.
- Частный интерфейс: `127.0.0.1:8787`; интерфейс с обязательным входом:
  `172.19.0.1:8789`, только в локальной сети Docker.
- Caddy обслуживает HTTPS напрямую на VPS и передаёт запросы только на интерфейс
  с обязательной авторизацией. На публичном IP нет слушателя 8787 или 8789.
- Настройки задаются отдельным systemd drop-in; секретные `.env` не меняются.
  Пример и Caddy-блок находятся в `deploy/mobile/`.
- Прежний Tailscale Serve к незащищённому локальному интерфейсу нужно отключить
  после проверки HTTPS. Сам Tailscale и другие приложения не отключаются.
- Восстановление доступа: открыть локальную панель на Mac и создать приглашение.
  Публичного сброса защиты или регистрации первого администратора нет.

`sslip.io` предоставляет DNS-имя по IP, содержание HTTPS-переписки через него не
проходит. Доступность имени зависит от этого DNS-сервиса; при смене имени сайта
потребуется повторная регистрация ключей. Установленный сертификат проверяется
обычным браузером. LTE нужно проверить на самом iPhone с отключённым VPN: новый
HTTPS-адрес тоже может ограничиваться мобильным оператором.
